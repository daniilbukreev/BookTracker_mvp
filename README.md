# BookTracker — Frontend MVP (этап 3)

На третьем этапе приложение работает автономно: каталог загружается из локального mock-модуля, а пользовательские записи хранятся в `localStorage`.

## Реализовано

- **Поиск книг**: поиск по названию, автору, ISBN и описанию книги; фильтры по жанру, диапазону годов, рейтингу и статусу в личной библиотеке; сортировка по названию, году и рейтингу.
- **Страница книги**: описание, автор, жанр, год, ISBN, число страниц и рейтинг каталога; добавление книги в библиотеку, выбор статуса, личная оценка, изменение и удаление записи.
- **Моя библиотека**: счётчики по статусам, доля прочитанных книг, фильтрация, поиск, сортировка, быстрое изменение статуса и удаление.
- Адаптивный интерфейс, состояния загрузки/успеха/ошибки/пустой выдачи, базовая доступность и переиспользуемые компоненты.
- Redux Toolkit slices и асинхронные операции на `createAsyncThunk`; данные в компонентах читаются через typed Redux hooks (`useAppSelector` / `useAppDispatch`).
- Unit- и компонентные тесты на Vitest + React Testing Library.

## Страницы и маршруты

| Маршрут | Страница | Назначение |
| --- | --- | --- |
| `/` | Поиск книг | Каталог, полнотекстовый поиск, фильтры и сортировка |
| `/books/:bookId` | Страница книги | Подробности и управление личной записью |
| `/library` | Моя библиотека | Просмотр, фильтрация и изменение личной коллекции |


## Архитектура

```text
src/
  app/                 Redux store и типизированные hooks
  components/          общие компоненты оболочки, обложки, карточки и статуса
  data/                локальный каталог mock-книг
  features/books/      типы книги и booksSlice
  features/library/    librarySlice и CRUD через createAsyncThunk
  pages/               три страницы приложения
  utils/               фильтрация, валидация и localStorage
  test/                настройка тестового окружения
```

`booksSlice` отвечает за каталог и состояния его загрузки (loading имитируется короткой задержкой mock-Promise). `librarySlice` отвечает за CRUD пользовательских записей. Функции доступа к `localStorage` изолированы в `utils/libraryStorage.ts`. Отдельные `createSelector` на этапе 3 не выделены: чтение state идёт через typed hooks прямо в страницах и компонентах.

## Модель данных

- `Book`: `id`, `title`, `author`, `description`, `year`, `genre`, `pages`, `isbn`, `cover`, `coverLabel`, `catalogRating`.
- `LibraryEntry`: `id`, `bookId`, `status`, `rating`, `updatedAt`.
- `ReadingStatus`: `want | reading | done`.

Одна запись `LibraryEntry` связывает книгу с личным статусом и оценкой. В MVP предполагается один локальный пользователь.

## Хранение

Ключ `booktracker.library.v1` в `localStorage`. При первом запуске создаётся демонстрационная библиотека из шести книг. Последующие изменения сохраняются в браузере и переживают перезагрузку страницы. Очистить демо-данные можно, удалив этот ключ в DevTools → Application → Local Storage.

## Валидация

- Годовой диапазон: годы должны быть неотрицательными целыми числами; начальный год не должен превышать конечный.
- Личная оценка: целое число от 1 до 5 либо отсутствие оценки.
- Статус выбирается только из трёх допустимых значений.

## Функция повышенной сложности

Реализован расширенный поиск по каталогу, встроенный в основной сценарий «поиск → просмотр книги → добавление → управление библиотекой». Поиск поддерживает одновременное применение текстового запроса, жанра, диапазона годов, минимального рейтинга и статуса чтения, а также сортировку. Фильтрация вынесена в отдельную чистую функцию и покрыта unit-тестами.

## Тесты

- `bookFilters.test.ts`: поиск, комбинация фильтров, статус, сортировка, валидация годов и оценки.
- `booksSlice.test.ts`: состояния асинхронной загрузки каталога (`pending` / `fulfilled` / `rejected`).
- `librarySlice.test.ts`: редьюсер библиотеки и основные async-состояния CRUD (`load` / `add` / `remove`).
- `BookCover.test.tsx`: компонентный тест доступного имени обложки.

## Ограничения этапа

Каталог статический, а асинхронная загрузка имитируется Promise с небольшой задержкой, чтобы в UI было видно состояние loading.
